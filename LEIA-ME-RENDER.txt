MARACANÃS — V15 PARA RENDER

FINALIDADE DESTA ENTREGA
Pacote adaptado para uma demonstração online com login obrigatório. Ainda não
é a versão final para operação compartilhada da equipe com dados reais.
Não foi publicado automaticamente: é preciso conectar seu repositório e
configurar o serviço na sua conta Render.

O QUE JÁ FOI PREPARADO
- Node serve o React compilado e a API no mesmo endereço.
- Domínio autorizado pelo Render e HTTPS em produção.
- Cookies HttpOnly, Secure e SameSite=Strict; CSRF nas operações de escrita.
- SQLite das contas, sessões, permissões e auditoria em disco persistente.
- Login sem cadastro público, senhas com hash, bloqueio de tentativas.
- Build, start, health check e render.yaml.
- Fontes e itens da V14 mantidos; uma coleta pesada por vez.

ATENÇÃO AO QUE AINDA É LOCAL
Os editais, decisões, propostas, documentos e chamados de suporte ainda
ficam no navegador. O novo domínio não acessa os dados do localhost.
Esta entrega não implementa backup diário completo, recuperação por código
via email, MFA ou colaboração com permissões para o funil.
O disco persistente protege as contas contra perda num reinício; não substitui
o backup independente de dez cópias solicitado. Não trate como concluído.
Use dados de demonstração até terminar essa migração e o backup isolado.

PUBLICAR NO RENDER — MÉTODO COM BLUEPRINT
1. Crie um repositório privado no GitHub.
2. Envie o conteúdo DE DENTRO da pasta Central_V15_Render à raiz dele.
   package.json, render.yaml, src e server devem ficar na raiz do repositório.
   NÃO envie data, node_modules, arquivos .sqlite, senhas nem tokens.
3. Entre em https://dashboard.render.com e conecte seu GitHub.
4. Escolha New > Blueprint e selecione esse repositório.
5. Revise a configuração antes de criar o serviço: ela usa Web Service
   Starter pago e disco persistente de 1 GB. Consulte os preços exibidos
   pelo Render. Criar/ativar recursos pode gerar cobrança.
6. Confirme a criação no seu painel. Aguarde o deploy concluir.
7. Use a aba Shell DO SERVIÇO EM EXECUÇÃO (não uma shell efêmera) e execute:

   npm run criar-admin

   Cadastre nome, login, email e senha de pelo menos 12 caracteres. Digite
   a senha diretamente no terminal: ela fica oculta. Não envie a senha no chat.
8. Abra a URL onrender.com exibida no painel e entre com essa conta.
   Não existe senha padrão. As contas do computador não foram enviadas.
9. Cadastre o acesso da cliente pela administradora se quiser uma conta própria.
   Funcionários atualmente consultam fontes quando autorizados; o funil local
   da administradora não é compartilhado com eles nesta versão.

SE CONFIGURAR MANUALMENTE (NEW > WEB SERVICE)
Runtime: Node
Build Command: npm ci --include=dev && npm run build
Start Command: npm start
Health Check Path: /api/health
Variáveis:
  NODE_VERSION = 22.16.0
  NODE_ENV = production
  ER_AUTH_DB = /var/data/auth.sqlite
Disk: mount path /var/data, tamanho inicial 1 GB
Use uma instância paga compatível com disco. Não escolha Static Site.
RENDER_EXTERNAL_URL é fornecido automaticamente pelo Render.
Se configurar domínio próprio, adicione APP_ORIGIN=https://seu-dominio
(somente a origem, sem caminho, login ou senha).

CONFERIR APÓS PUBLICAR
- /api/health retorna {"ok":true}.
- A raiz abre a tela de login com a logo da Maracanãs.
- Login inválido falha; logout encerra a sessão.
- /api/sources sem cookie deve responder 401.
- Confira as buscas PNCP e das cinco fontes na rede do Render: acesso local
  anterior não garante que o portal permita coleta da hospedagem.
- Após reiniciar, a conta deve continuar disponível graças ao disco.
- Editais do navegador não constituem backup do servidor.

ATUALIZAÇÕES
Envie alterações ao repositório conectado. O Render recompila a interface.
Não apague o disco persistente e não envie seu banco de contas ao GitHub.

TESTES DO PACOTE
Compilação da interface e onze testes de autenticação, autorização, CSRF,
rotas, itens, domínio, cookie seguro, proxy e arquivos estáticos.
Além disso, verificação de execução em modo produção em ambiente isolado.
Validação da infraestrutura real depende do primeiro deploy no Render.
